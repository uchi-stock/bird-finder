# bird-finder

「声しか知らない鳥」を見つけられる野鳥図鑑の試作です。鳴き声のオノマトペ、大きさ、色、行動、場所、季節から、多摩川中流域で見られる鳥を絞り込みます。

- 公開URL: https://uchi-stock.github.io/bird-finder/
- 構成: `frontend/`（Vite + React + TypeScript）。ログイン・バックエンドなし
- 鳥種データは一般的な図鑑知識に基づく暫定値です。出典の検証は今後の課題です

## インセプションデッキ

プロジェクトの方向性を残すためのメモです。
開発経緯から起こした項目が中心で、推測を含む項目には「（仮）」を付けています。
違っていれば直してください。

### 1. なぜやるのか
- 鳴き声は知っているのに、名前も姿も結び付かない鳥が多い
- 図鑑は名前を知っている前提で、「声しか知らない」人が引ける導線が少ない
- 野外でスマホ1台で、見た・聞いた手がかりから候補を絞れるようにする

### 2. エレベーターピッチ
- 声しか知らない鳥を知りたい、野外で歩く人のための
- 「鳥さがし」というWebアプリ（PWA）は
- オノマトペ・大きさ・色・行動・場所・時間から候補の鳥を3種までに絞る図鑑である
- 名前検索型の図鑑と違い、名前を知らなくても引ける
- 鳥の確率ではなく「近さ」で示し、断定しない

### 3. パッケージデザイン（仮）
- 開いてすぐ、現在地と現在時刻が入った状態で条件カードを横にスワイプして答えられる
- 結果は鳥の写真と近さだけで、詳細・鳴き声・捕まえるは拡大画面にある
- 捕まえた鳥は図鑑にたまり、みんなの発見は地図で見られる

### 4. やらないことリスト
| やる | 今はやらない | 後で決める |
|---|---|---|
| 候補を3種までに絞る | 画像や音声での自動判定 | 識別精度の評価 |
| 端末内の図鑑・コレクション | ログイン・端末間の引き継ぎ | アカウント導入 |
| 匿名で任意の共有（位置はぼかす） | 共有の取り消し・投稿の編集 | 通報・削除の運用 |
| 多摩川中流域の鳥種データ | 全国の鳥種 | 対象地域の拡大 |

### 5. 技術構成
- フロントエンド: Vite + React + TypeScript、GitHub Pagesで配信
- 判定: 端末内のルールベース（`frontend/src/domain/scoring.ts`）。外部のAIは使わない
- 共有: AWS（API Gateway + Lambda + DynamoDB）。共有の地図のためだけに使う
- 詳細は下の「技術構成の判断」を参照する

### 6. ご近所さん（関わる人・もの）
- 利用者: 野外で鳥に出会う人（iPhoneで使う想定）
- データ元: 写真・鳴き声はWikimedia Commons、環境判定はOpenStreetMap
- 運用: 開発者1人。変更はすべてIssue → PR → 自動マージで進める

### 7. 夜も眠れない問題（リスク）
- 鳥種データが暫定値で、出典の検証が終わっていない
- 位置情報の共有で自宅が分かってしまう（対策: グリッド化・ずらし・自宅周辺の除外・共有は任意）
- 外部API（Overpass・Wikimedia）の利用制限・障害
- iOS Safariで使えないWeb APIがある（対策: フィーチャー検出）

### 8. 期間（仮）
- 試作を素早く出し、実機（iPhone）の使用感でスマホ上のフィードバックを回す
- 識別精度の評価と鳥種の拡充は、方向性が固まったあとに行う

### 9. トレードオフ・あきらめるもの（仮）
| 守るもの | 後回しにするもの |
|---|---|
| 野外で片手で素早く答えられること | 条件の網羅・細かい入力 |
| 位置のプライバシー | 共有の精密さ |
| 動くものを早く出すこと | 厳格なlint・カバレッジ（現状は閾値85%のみ） |

### 10. 何がどれだけ必要か
- 必須: 声・姿から候補を絞る、現在地と時刻の自動入力、図鑑、スマホ表示
- 次: 鳴き声／姿／両方の入口の切り替え（Issue #60）、共有地図の公開（Issue #46）
- 選択肢の構造は[`docs/selection-options.md`](docs/selection-options.md)にMermaid図でまとめている
- 識別精度の測り方と実測値は[`docs/accuracy.md`](docs/accuracy.md)に記録している

## 技術構成の判断（フェーズ3の見直し結果）

standard-tech-stackの「選定の考え方」に沿って要否を判断した結果は次のとおり。

| 要素 | 判断 | 理由 |
|---|---|---|
| ログイン | なし | 個人情報を扱わず、匿名で共有する（図鑑は端末内の保存） |
| バックエンドAPI | **共有のためだけに追加**（AWS: API Gateway + Lambda + DynamoDB） | 「みんなが見つけた鳥」を地図に出すため。位置は端末側でぼかしてから送り、記録は期限なく保存する（`backend/`） |
| ホスティング | GitHub Pagesのまま | S3 + CloudFrontはAWSの準備が必要なため見送り |
| PWA | 採用 | 野外でホーム画面から素早く開くため |
| 共通UI規約 | 適用 | 共通フォント、バージョンと更新日時の表示 |

### 再検討の条件
- 図鑑を端末間で引き継ぎたい: ログインとバックエンドAPIを追加する
- 独自ドメイン・キャッシュ制御が必要: S3 + CloudFrontへ移行する（AWSアカウントとGitHub Secretsが必要）
- Overpass APIの利用制限に当たる: 自前のAPI経由へ切り替える
- Bootstrap 5.3への移行: 既存CSSのクラス名との衝突を整理してから行う
