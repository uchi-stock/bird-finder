# 識別精度の記録

想定した入力（評価シナリオ）に対して、正解の鳥が候補に出る割合を記録する。
重みや鳥種データを変えたら、この表を更新する。

## 測り方

- シナリオは`frontend/src/domain/evalScenarios.json`にある（88件。44種それぞれに2件以上）
- 判定は画面と同じ経路（`identify` → `pickTop`）で行う。実装は`frontend/src/domain/evaluate.ts`
- 「声だけ」は、姿が見えず、聞こえた声・環境・時間帯・月だけを入れた入力
- 「姿だけ」は、声が分からず、大きさ・色・場所・行動・環境・時間帯・月を入れた入力
- 入力は鳥種データの丸写しにしていない。一般の人が答えそうな内容にしている
  - 色は目に付いた1〜2色だけ
  - 大きさは1段ずれることがある
  - 声はひらがなの聞こえたままで、データの表記と違うことがある
  - 環境がデータと違う場合も含む（例: 駐車場のハクセキレイ、川のヨシ原のオオヨシキリ）
- CIのテスト（`evaluate.test.ts`）が下限を持ち、精度が下がる変更は失敗する

## 分かったこと（2026-11-16）

- 声だけの入力が弱い。声が合っていない鳥が上位に来る
  - 例: カモ類の声を入れても、ハシボソガラス・カワラヒワ・スズメが上位に出る
  - 声の一致が弱いとき、環境・時間帯・季節・「よく見られる」の加点だけで順位が決まっている
- よく見られる鳥（カワラヒワ・スズメ）が、条件に合う鳥を押しのけることがある
- 環境がデータと違うと、正解が候補から落ちやすい（ハクセキレイ、チョウゲンボウ）

## 改善した内容（2026-11-16、Issue #78）

原因ごとに直し、そのつど数値を測った。シナリオは書き換えていない。

| 直した内容 | 全体の1番目 | 全体の候補内 |
|---|---|---|
| 改善前 | 54.5% | 77.3% |
| 「見えない（声だけ）」で自動で入る「鳴く」を採点しない。小さい仮名の違いを同じとみなす | 65.9% | 85.2% |
| 声の繰り返しの回数の違いを吸収する。複数の聞こえ方を区切りごとに比べる | 68.2% | 88.6% |
| 鳥種データを実態に合わせる。普段声を出さない種を、声が聞こえたときの候補にしない | 71.6% | 90.9% |
| 半濁音と濁音の違いを同じとみなす。一部だけの一致を少し弱く扱う | 73.9% | 92.0% |

鳥種データで直した点は次のとおり。

- カモ類・サギ類の時間帯に「日中」を追加した（日中も水辺で普通に見られる）
- モズの環境に「草地・農地」を追加した
- ハクセキレイの環境に「住宅街・市街地」を追加した
- チョウゲンボウの環境に「草地・農地」「川辺・水辺」を追加した
- オオヨシキリの環境に「川辺・水辺」を追加した
- アオジの環境に「森・林・公園」を追加した

## 残っている外れ（直していない）

似た種どうしや、大きさの見誤りによるもので、今の入力項目では区別が難しい。

- 小さい茶色の鳥（ホオジロ・アオジ）は、よく見られるカワラヒワ・スズメに負ける
- カモ類どうし、サギ類どうしの声は、表記が似ていて区別しにくい
- 大きさを1段小さく見積もると、その大きさの別の鳥が上に来る（オオタカ→オナガ、コガモ→カイツブリ）

無理に合わせると、シナリオへの合わせ込みになるため、ここで止めた。
改善するなら、模様（腹の縞・目の周りの色など）の入力項目を増やす方向になる。

## 注意

- この数値は、作ったシナリオに対する値である。実際の野外での正解率ではない
- シナリオを正解しやすいように書き換えて数値を上げない。直すのは判定の側である
